# 交易方法与验证计划｜2026-10-28 v1

本版由用户“按照方法建议优化策略”的请求授权制定。当前阶段为研究验证，不代表策略已证明盈利、不代表订单授权。原有 NVDA 长期归属、已关闭交易及其原始入场信息不追溯修改。数字风控限制是本次选定的执行约束，不是统计最优参数或实际亏损保证。

## 1. 先解决什么

目标是把交易收敛为能重复执行、能追查失效原因的方法。主动方向优先研究 `triple_screen_rf`：大盘条件通过，周线趋势向上，日线回调后向上触发，按固定入场 ATR 管理风险。现有代码只用价格和成交量，**没有成长股基本面筛选**；它不能自动把候选称作优质成长股。

今天直接读取的 [GitHub 实验室](https://github.com/Marla62/triple-screen-scan/blob/main/output/lab.md) 截至 2026-09-17，2023-09-21 至 2026-09-17 的组合年化／最大回撤分别为：三重滤网 -2.47%／-28.18%，带大盘过滤三重滤网 -10.41%／-33.07%，布林回归 4.36%／-24.95%，月度动量带过滤 24.55%／-38.26%，SPY 20.99%／-19.00%。旧实现对趋势策略给出负面证据，不能用“更符合偏好”代替盈利验证。

旧实验室每笔 2%、单票 25% 的风险和仓位设置与实盘不一致；另有资金时序、未平仓估值及数据缺失处理问题。先修正这些基础，再判断方法。改后的收益必须重新在 GitHub 产生；旧表不能重命名为新版本成绩，也不能按风险比例缩放成预测。

## 2. 冻结研究规则

- 技术候选：已有 `triple_screen_rf`，固定参数，不同时搜索几十种组合挑最高收益。SPY 当日缺失或尚无有效 SMA200 时禁止生成新入场信号。待触发信号在已完成日的大盘过滤失效后取消，已有持仓仍按原退出规则管理。
- 周线条件使用过去完整周加当日已知收盘对本周的部分更新，不能使用未来周五数据。日线 Force Index 回调与 Impulse 条件沿用代码；逐笔留档对应指标。
- 入场：信号出现后从下一常规交易时段观察买入触发价；价格恰好触及时也算触发，未触发时按原规则下移。跨日触发沿用真实待触发价。实际若跳空，成交价格和股数必须重核，不能保证按触发价成交。
- 退出：初始止损为实际入场价减 2×入场 ATR；使用成交前一已完成日 ATR14（项目 EWM 口径）并固定。后续止损取上一止损、初始止损、建仓后最高价减 2×固定 ATR 的最大值，只升不降。研究回测采用收盘更新、下一交易时段生效的日线跟踪口径，不伪称盘中实时跟踪。
- 排序：每日观察名单和组合模拟均使用当时已知的信号强度；单票历史胜率保留作诊断，不作为“最好股票”结论。同一分数用代码排序稳定打破并列。
- 不摊低亏损仓，不把短线亏损仓改为长期。初始验证阶段不加仓；后续若加入金字塔加仓，必须另开版本、验证并重新计算整笔与同主题风险。
- 基本面、估值、财报日期及流动性另做人工核查，使用当时已披露来源。缺记录则不提出实盘计划。研究技术回测未覆盖这一层，人工筛选后的结果必须单独记录，不能冒充原技术策略的历史成绩。

## 3. 资金与风险

长期 35%、中期 22.5%、短期 20%、现金 22.5% 的目标保持。分区是预算方向，不是每天必须花完的额度。现金、单票、分区和风险限制同时检查，取最严格结果，不融资。

| 项目 | 本版规则 |
|---|---|
| 当前主动新仓 | 研究阶段暂不开放；原有仓位继续按自身规则管理 |
| 未来小额试行 | 完成证据复核并明确同意进入试行后，每笔计划风险 0.25%，同时最多 2 笔 |
| 后续单笔上限 | 中期、短期均不超过总净值 0.5%；短期旧上限 0.6% 收紧至 0.5% |
| 主动合计计划风险 | 不超过总净值 2%，包含有效入场挂单和拟新增仓位 |
| 同板块／同主题主动风险 | 合计不超过总净值 0.5%；长期同主题持仓另计入总敞口复核 |
| 单票市值 | 常规不超过总净值 10%；长期初始单票不超过 5% |
| 暂停复盘 | 沿用月度交易亏损 3%、资金流调整后的运行峰值回撤 5%；口径无法确认时不声称已通过检查 |

逐笔风险按“股数×入场到保护止损的距离＋预计费用”核算，跳空与滑点可能使实际损失超过计划。组合研究保守地占用每笔原始风险预算，不因为浮盈就释放额度。长期仓没有由主动 2% 预算提供的损失保护。

代码研究示例按每笔 0.5%、单票 10%、合计 2% 测试；这是技术研究上限，不是已经启用实盘。示例账户没有完整模拟真实长期／中期／短期分区、相关主题限制或实际 IBKR 佣金阶梯，不能直接照抄示例股数。实盘建议必须再由 `rules.json`、IBKR 仓位和挂单共同约束；未来试行使用更低的 0.25%。

## 4. 验证及晋级门槛

1. **先通过实现验证。** 合成行情用于验证时序、触价、风险、费用、退出和数据缺失处理，只证明代码行为，不证明收益。
2. **修正后重做远端历史研究。** 使用同期间数据，分别比较旧布林回归、三重滤网、带过滤三重滤网、月度动量与 SPY，披露实际敞口和风险差异。今日已看过的历史是开发样本；分年收益、事后切开时间段均不自动成为独立样本外证明。
3. **独立检查成本与股票池。** 5bp 往返比例成本只是简化情景；需以实际小额订单佣金、买卖价差、可成交报价与保守滑点核算，并检查费用翻倍情景。当前成分股加加入日期仍缺历史剔除／退市公司；没有完整时点名单就保留幸存者偏差警示。
4. **冻结后积累前瞻证据。** 从远端部署并实际开始逐日留档之日起计时，保存不可事后改写的信号、拟入场、跳过原因、可成交条件、净收益和退出。修改规则要另立版本，重新标记验证期；目前尚未启动前瞻采集，不伪造开始日期。
5. **每月明确复核结论。** 首次政策复核日期为 2026-11-30；自第一条有效前瞻记录起 12 周作一次去留决定。这只是人工复核计划，没有新建自动提醒。到时只能选择：证据充分则进入小额试行、以明确期限继续实验、修改后重新冻结、或放弃该实现。30／50 笔交易或经过 12 周都不是有效性的证明。
6. **试行前须完整审阅。** 组合成本后表现、回撤、平均盈亏、收益集中度、样本不确定性及不同市场环境均要披露，并与同期间 SPY、按实际股票／现金敞口匹配的基准比较。成本后无优势、结果由少数交易驱动且不稳健、回撤无法接受、记录对不上，都不升级。个人最大可接受回撤仍未知，不能仅凭自动检查宣布可实盘。

任何阶段出现行情/账户无法核对、保护规则不能执行、风险预算超限，立即暂停新增主动仓，先管理已有仓。连续盈利不是升级条件，连续亏损也不能用放大仓位追回。是否从 0.25% 提高到 0.5% 单独复核，不自动执行。

## 5. 现金部署与每日报告

每次日报分别列：长期距离 35% 的缺口、当日有证据的长期候选及分批条件；主动研究候选与尚未通过的门槛；到下次复核前需要补齐的材料。没有合格标的可以继续保留现金，但必须说明卡在哪一项。

长期资金不必等待主动策略研究结束。提出长期分批计划前，必须有公司基本面与估值依据、逻辑失效条件、财报安排、与已有 NVDA 的主题敞口检查，以及明确的金额和价格有效期；未成交计划不写入成交记录。当前已有 NVDA 不自动套用新趋势止损。

本版保留 `config.json` 的 `bb_revert` 作为原扫描基线，趋势候选只作研究；日报必须先读本地规则，不能把远端旧扫描信号当新规则已验证的买入指令。只读 GitHub main 的最新扫描和实验室，禁止使用本地 output、备份或旧缓存，也不恢复本机扫描任务。提交、推送和远端运行不在本次已执行范围内。
